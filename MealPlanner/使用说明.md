# Meal Planner 本地恢复版

## 打开网站

双击本文件夹中的 `Start.command`，浏览器会打开 http://127.0.0.1:8111/ 。
登录页面只填用户名 `demo`，不需要密码。也可以创建新的演示用户。
启动窗口保持打开；按 Control+C 停止。下次启动会保留你添加的数据，不会重新覆盖。

本机已经安装依赖。若把压缩包解压到新文件夹，首次启动需要 Python 3.12 和联网安装依赖；以后可离线运行。不要单独移动 .venv 文件夹。

## 数据

全部数据为虚构演示数据，包括 100 道不同菜谱（10 种菜系）、20 个用户（其中 10 个厨师）、82 种食材、190 条评论、20 份每周饮食计划、280 个计划条目，以及关注、评分、饮食标签。
100 道菜谱的可读数据在 `demo_recipes.json`。
实际数据库保存在 `data/mealplanner.db`。关闭网站后复制整个项目文件夹即可备份。

## 恢复内容与限制

保留原 Flask 网页和模板，数据库改为 SQLite，以免依赖失效的云服务器和额外 PostgreSQL 服务。
SQL 已按 SQLite 调整；`schema_sqlite.sql` 是实际使用的结构，`schema.sql` 是重建的 PostgreSQL 结构参考，未在 PostgreSQL 上运行验证。
本次恢复的是 Part 3 网站；不包含 Part 4 PostgreSQL 全文检索、数组和复合类型扩展。
修复了搜索查询、评论跳转、取消关注回滚和启动入口；为饮食计划访问及操作增加了用户归属检查。
采用原项目的无密码演示登录，只绑定本机地址。此版本用于本机展示；公开发布之前需要增加正式认证并配置托管。
食材份量及饮食标签是演示数据，不用于实际营养或过敏判断。

已在独立测试数据库验证创建菜谱、添加食材、创建/修改/删除饮食计划、周视图、购物清单、注册/删除演示用户、权限限制，以及重新初始化不会覆盖已有数据。
